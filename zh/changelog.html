更新日志 ​

从首个演示版本到 PaperSeek 1.0.0-beta5，记录各版本的功能、改进与升级事项。

1.0.0-beta5 ​

检索结果会标出论文的发表期刊分区和会议录用信息，可直接导出到文献管理器，数据源新增三个中文数据库。可从更早的 1.0 测试版原地升级，无需迁移。

期刊分区与会议录用 ​

  • 结果标注中科院分区与 Top、JCR 分区与影响因子、CCF 类别，数据来自 ShowJCR。首次检索时自动下载到本机；设置 → 数据源 → 期刊分区数据中可查看版本、更新或导入本地文件。
  • 会议录用信息显示会议、年份以及 Oral、Spotlight 或 Poster，来自 PaperHub 与 OpenReview。只计入会议主会场、NeurIPS Datasets & Benchmarks 和 TMLR 的录用。
  • 结果页可按中科院分区或 Top、JCR 分区、CCF 类别和录用情况筛选，并可按影响因子排序。详细书目信息还会显示 OpenAlex 开放影响力（不是影响因子）。
  • 中文期刊标注北大核心，以及 CSSCI 来源期刊、来源集刊或扩展版，并注明各目录版本，目录由 PaperSeek 整理。按中文刊名或曾用名匹配，每类在结果页都可单独筛选。
  • 综述选文显示同样的标签，也能据此筛选。文献计量新增期刊分区页，展示分区、分级的分布，以及期刊与会议分级表。

导出 ​

  • 全部结果和所选结果都可导出为 BibTeX 和 RIS，直接导入 Zotero、EndNote、JabRef；期刊论文、会议论文、预印本使用各自的条目类型，会议录用信息写入备注字段。MCP 的 export_results 也支持这两种格式。
  • 来自 OpenAlex、Crossref、PubMed、Semantic Scholar 的记录，在数据源提供时保留 ISSN、卷、期和页码。

数据源 ​

  • 新增万方数据（需自己的 AppKey）、国家哲学社会科学学术期刊数据库和中华医学期刊库。检索计划和检索式都用中文构建，每个库使用各自的检索式写法。
  • 计算机顶会数据源同时检索 OpenReview，补充 PaperHub 未收录的已录用论文。

设置 ​

  • 网络代理移到设置 → 通用。移除代理会立即生效。OpenReview 和 ShowJCR 下载使用数据源的代理范围。

问题修复 ​

  • 模型回复缺少结尾括号时会补全后采用，不再失败；在后面段落中被截断的回复会进入修复流程，而不是被截短后采用。
  • 综述某一节写出的段落多于计划时，多出的段落会在长度限制内合并保留，并标记为需要核对。
  • 切换模块后综述选文不会丢失；综述保存后，临时草稿随即释放。
  • MCP Docker 镜像改为基于本次发布的程序包构建。

升级说明 ​

  • 从更早的 1.0 测试版升级：用 pip 安装 1.0.0b5，或在 Docker 中设置 PAPERSEEK_VERSION=1.0.0-beta5；数据无需迁移。详见从更早的 1.0 测试版升级。
  • 分区和录用标签在检索结束时写入，升级前的结果没有标签，重新检索即可。重新创建文献计量分析即可看到期刊分区页。
  • 分区表从 GitHub 下载。无法访问 GitHub 时，可在设置 → 通用中设置代理，或导入本地文件。

详见结果与历史和数据源。

1.0.0-beta4 ​

综述先设置范围，可按主题挑选文献，并说明哪些文献没有用上、为什么。排序改为并行处理，打分和理由分别显示进度。可从更早的 1.0 测试版原地升级，无需迁移。

文献综述 ​

  • 先设置写作范围，再选择文献。可以设置章节数、每章段落数，以及按输出语言计量的每段长度；每档篇幅都会给出建议的文献数量。
  • 按主题自动挑选考虑按检索排名排列的前 256 篇有有效摘要的文献，挑出覆盖不同主题的文献，并给出每篇的理由。它不会创建任何内容，也不计入写作次数。
  • 一篇综述最多可使用 256 篇文献，可从全部检索结果中手动选择。
  • 生成的每个段落计划最多使用 10 篇文献。大纲未采用的文献会列出并附理由；把它加入某一章即可重新纳入。
  • 写作时只有说明理由才能不引用计划文献。证据核对会复查每条理由，标出可能不成立的理由，未能完成核对的理由会标记为需要人工核对。
  • 段落中无法对应到具体论断的引用会单独列在段落下方，Markdown 和 Word 导出同样保留。正文不再出现内部证据编号。
  • 某一节失败不再中断其他章节；重试只会重写缺失或需要修订的部分。
  • 证据引文保留摘要原文及其语言，只有能可靠找到更短的支撑片段时才会截短。

检索排序 ​

  • 打分和“排序理由”分批并行生成，并分别显示进度。
  • 使用自带密钥时，提供方可能同时收到多个请求，其限速仍然适用。

升级说明 ​

  • 从更早的 1.0 测试版升级：用 pip 安装 1.0.0b4，或在 Docker 中设置 PAPERSEEK_VERSION=1.0.0-beta4；数据无需迁移。详见从更早的 1.0 测试版升级。
  • 尚未写出正文的综述，下次生成大纲时会重新提取证据；已有正文的综述保留原有证据。

操作步骤和限制见文献综述。

1.0.0-beta3 ​

零结果检索会谨慎地再试几次，数据源节流在所有运行中的任务之间共享，还可以让请求通过你自己的代理发送。可从更早的 1.0 测试版原地升级，无需迁移。

检索 ​

  • 检索没有找到论文时，PaperSeek 最多再尝试两次。每次都参考之前的检索式及其结果数，并先与你的问题核对，确保必需的概念、关系和限制条件都保留。仍然没有结果时，检索会结束并说明原因。
  • 补充检索时如果无法连接数据源，检索会以零结果结束并给出提示，不再整体失败。
  • 模型给出的检索式如果之前已经执行过，会把之前的结果告诉模型并再请求一次，仍然重复才停止调整。
  • 模型在答案外附带说明文字时，意图核对也能正确识别。

数据源 ​

  • PubMed 的限流提示会被识别为限流，不再当作网络错误，PaperSeek 会等待后再重试。
  • 所有运行中的任务对同一数据源共享节流和冷却时间，重试也包括在内。无论同时运行多少个检索，arXiv 都是每 3 秒一次请求。
  • 一般故障约 1 秒后重试，只有限流才会等待更久。
  • Web of Science 可以重新选择。

网络代理 ​

  • 设置 › 数据源 › 网络代理 可以让请求通过你自己的 HTTP(S) 代理发送。可以勾选：大模型请求、按网络地址限速的数据源（arXiv、Crossref、PaperHub，以及未填写密钥的 PubMed 和 OpenAlex）、其他数据源。其余请求按系统代理设置发送，本机模型地址始终直连。
  • 填写多个代理时轮流使用。地址在本机加密保存，只显示主机和端口，清空已保存的密钥 时会一并删除。
  • 服务器部署也可以使用 PAPERSEEK_PROXY_URLS 和 PAPERSEEK_PROXY_SCOPE，详见网络代理。

任务运行 ​

  • 最多同时运行 4 个检索和综述任务，其余排队等待。PAPERSEEK_MAX_CONCURRENT_RUNS 可修改上限，设为 0 表示不限制，详见并发任务。

升级须知 ​

  • 从更早的 1.0 测试版升级：用 pip 安装 1.0.0b3，或在 Docker 中设置 PAPERSEEK_VERSION=1.0.0-beta3；数据无需迁移。详见从更早的 1.0 测试版升级。
  • 新增设置都是可选的。不设置时行为与之前相同，只是现在最多可同时运行 4 个任务。

1.0.0-beta2 ​

维护版本。模型回答出现部分错误时，综述和检索排序会继续进行；运行中的检索会保留在历史记录里；Docker Compose 默认只对本机开放。可从 1.0.0-beta1 原地升级，无需迁移。

文献综述 ​

  • 少数论文提取不到可用证据时，综述不再整体失败。这些论文会被排除在大纲之外，并在文献列表中标出；其余部分照常进行，再次生成大纲时只重试这些论文。
  • 即使模型把某条引文写错，论文仍保留其余与摘要相符的引文。用省略号（…）拼接的引文会拆成几段分别核对，不再整条作废。
  • 大纲遇到没有已核对证据的论文时不再中断：该论文会从规划中去掉，失去全部来源的段落会从已核对的证据中重新分配来源。

检索排序 ​

  • 模型只给部分候选文献打分时，已给出的评分会保留，只重新请求缺少评分的文献。仍未评分的文献按原有顺序排在已评分文献之后，检索会给出提示。
  • “排序理由”改为分小批请求，较长的理由（尤其是中文）不会再被截断；回答中漏掉的文献会再请求一次。

历史记录 ​

  • 排队中和运行中的检索现在会出现在检索历史里，刷新页面后依然可见，运行期间不能删除。

自托管 ​

  • 随附的 Docker Compose 文件默认只在本机发布 PaperSeek（127.0.0.1:8765）。如需从其他设备访问，请在 .env 中设置 PAPERSEEK_HOST=0.0.0.0 并做好访问保护；PAPERSEEK_PORT 仍用于修改端口。
  • MCP 的 Docker 镜像可以重新从干净的源码构建。
  • 各发行包中的第三方声明表格显示正常。

文档站 ​

  • 在首页，手指搭在触控板上或滑动结束时的余量，不会再让页面跳到其他板块。

升级须知 ​

  • 从 1.0.0-beta1 升级：用 pip 安装 1.0.0b2，或在 Docker 中把 PAPERSEEK_VERSION 设为 1.0.0-beta2；数据无需迁移。详见从更早的 1.0 测试版升级。
  • 如果从其他设备访问 Docker 部署，请使用新的 compose.yaml，并按上文设置 PAPERSEEK_HOST。

1.0.0-beta1 ​

PaperSeek 1.0.0-beta1 是一次完整的架构重构，包含不兼容变更。本次围绕共享研究应用重建任务执行、前端、存储边界与分发方式，并为已有用户数据提供明确的迁移路径。

三个模块与独立历史 ​

  • 重新设计的工作区：文献检索、文献计量、文献综述位于可折叠侧栏，各模块保留独立历史，账户位于左下角。
  • 设置页包含模型 API、数据源、通用和用户数据：可清空已保存的密钥或全部历史，均需输入确认语；清空历史前会先停止正在运行的任务。
  • 新增针对实际获取去重候选集的初步计量：原生字段覆盖、关键词共现、受限文献耦合、网络缓存及独立导出；LLM 评分仍为子集。
  • 综述整合选文献、大纲、正文和引用证据，新综述保存可用的来源图快照。
  • 历史记录可以重命名，原检索问题和设置保持不变。

通过 pip 安装时版本号写作 1.0.0b1，Docker 镜像标签为 1.0.0-beta1。

在线版 ​

  • 登录后使用 PaperSeek 服务：内置模型、无需密钥，公测期间每日免费 20 积分。一次检索或计量消耗 1 积分，一篇综述消耗 5 积分，在任务开始时扣除；任务失败或取消会退回。
  • 自带密钥：在设置中把模型连接和数据源密钥保存到账户，任务使用你自己的 API，不消耗积分。此模式下，除 arXiv、Crossref、PaperHub 等无需密钥的数据源外，其余数据源（包括 OpenAlex、PubMed、Semantic Scholar）都必须提供密钥。
  • 不登录也可以在表单中填写自己的密钥，做一次临时检索。结果只保存在内存中，不会进入历史。

按职责重建架构 ​

  • 分离 paperseek_core、paperseek_app 与部署适配层：核心负责召回、检索式迭代、引用扩展、排序及数据源／模型协议；应用层负责提交、执行、持久化与查询；社区版和在线版各自实现部署与存储适配。
  • Web、CLI、HTTP API 和 MCP 共用应用层。检索核心不依赖 FastAPI、账户认证、SQLite 或 Supabase。
  • 在线版与社区版共用同一套检索实现和研究页面。
  • 以 Vue 3、TypeScript 和 Vite 重建前端。两端共用研究页面，通过版本化 /api/v1 契约通信，并由后端生成 API 类型以校验接口一致性。
  • 使用明确的异步工作流、httpx 客户端和 Pydantic 边界模型，移除废弃的运行入口。

持久任务、取消与恢复 ​

  • 将保存的检索建模为数据库中的任务，统一 worker 租约、顺序事件、检查点与结果产物。社区版可从已提交的兼容检查点恢复中断任务。
  • 页面通过任务快照、事件回放和 SSE 恢复已保存的状态；浏览器重连无需重新提交检索。
  • 统一取消与执行权校验，阻止失去租约的旧 worker 或取消后迟到的提供方响应提交结果。
  • 区分数据源／模型故障与持久化故障：可选召回或排序环节失败时可以提示警告并降级，结果保存失败则不能显示为成功。
  • 引入 Alembic 管理的 SQLite 版本迁移和显式迁移命令。社区版使用 SQLite 与本地文件。在线版未登录时的检索只是临时运行，不进入历史。

社区版可由单个本地服务运行 API 和内嵌 worker，也可分开运行。浏览器重连只恢复页面状态；服务中断的任务按检查点恢复执行。

完整的研究工作区 ​

  • Vue 3 界面，中英文切换，统一导航和分阶段任务状态。
  • 从研究问题出发的检索式迭代、有边界的召回、相关性排序与可查看的检索过程。
  • 八个学术数据源集成，各自的领域与访问设置。
  • 本地融合、Embedding + Rerank、System One 三种初排序方式。
  • 基于 OpenAlex 的引用扩展与交互图谱。
  • 历史任务、筛选、选择及完整 CSV/JSON 导出。
  • 实验性摘要综述：可编辑大纲、分节写作、版本、引用和 Markdown、Word、BibTeX 导出。

一套应用，多种入口 ​

Web、六命令 CLI、版本化 HTTP API 和独立的同版本 MCP 适配器共用应用服务。社区版将数据保存在本地 SQLite 和文件中；在线产品增加账户、服务模型、排队与隔离存储。

升级须知 ​

需要 Python 3.12+。旧 Python 导入路径、内部 API、前端接口以及废弃的 CLI／配置入口不再保留。0.2 用户数据与仍有效的环境配置通过显式命令迁移，新运行时使用新配置名称，不再回退读取旧名称。详见迁移指南与架构说明。

检索使用数据源原生摘要与元数据，不再提供独立的跨源摘要或引用数补全配置。

0.1.0 ​

2026 年 6 月 2 日 · 首个演示版本

首个版本建立了从研究问题到文献列表的基本流程：

  • 输入中文或英文研究问题，由 LLM 生成查询，并根据数据源结果多轮放宽或收窄检索范围。
  • 整理文献元数据，由 LLM 给出相关性评分与简短理由。
  • 通过 OpenAlex 扩展引用关系，提供可拖拽、缩放和平移的引用图谱。
  • 在网页中搜索、筛选和选择结果，导出 CSV。
  • 提供本地网页、命令行、Docker 部署和可选 Agent Skill。
  • 支持模型服务商、兼容接口与本地 Ollama。

该版本的发布页仅提供提交历史，没有单独列出功能；以上按 0.1.0 标签下的 README 整理。
